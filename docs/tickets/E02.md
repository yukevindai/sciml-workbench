# E02 — Provider interface and configuration

Status: adapter implemented and offline tests passing; live account/model acceptance pending.

`workbench.model_provider` provides a small provider protocol and one Anthropic Messages adapter using the existing constrained `httpx==0.28.1` transport. API version is `2023-06-01`, adapter version is `anthropic-messages/1.0`. No additional SDK, browser dependency or public API contract is introduced.

Configuration validates model identifiers and private credentials. A non-generating Models API lookup resolves configured aliases before any generation on that instance. Generation accepts trusted project/classified context, effective policy and registered Pydantic tool definitions. It checks exposure, tool/model allowlists, byte bounds and per-request limits before sending. Returned calls must name offered tools and match strict input models; unknown block types, duplicate call IDs, malformed usage, inconsistent stop reasons and unexpected model identity fail closed. Calls are returned for E03 dispatch and never executed by the provider.

The adapter emits usage categories, resolved model, stop reason and version metadata. Cost stays unknown. Timeouts, rate limits, authentication failures, outages, malformed/oversized replies and echoed credentials become safe typed errors without raw provider messages. Uncertain billable outcomes mark usage unknown; there are no hidden retries. Redirects and environment proxies are disabled. Context/results omit content from representations, and the adapter performs no logging or archive writes. Known provider-key canaries are blocked outbound and inbound, including JSON-escaped inbound echoes. Comprehensive credential/content redaction across tools, history, memory and exports remains E14.

The current call interface consumes an already assembled classified context snapshot; E04 owns conversational history construction. E05 must reserve and settle aggregate budgets and enforce monetary ceilings. B11/D11 still gate the worker, so this change does not enable agent execution.
