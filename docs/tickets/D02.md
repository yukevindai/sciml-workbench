# D02 — Immutable local storage

Status: implemented; local Windows and Linux/PostgreSQL acceptance passed on September 19, 2026.

Prerequisite: [D01](D01.md). Tested working tree based on `36a68ba42f6d23cc00b5f55ed244b0164a33842b`, including the uncommitted D01 implementation. No implementation commit or push was made in this task. The [storage contract](../storage.md) describes consumer behavior, filesystem requirements and cleanup limits.

## Changed behavior

- `LocalStore.put` stages exact immutable bytes in a private directory on the blob filesystem, synchronizes and verifies the staged file, and publishes with an atomic hard link that cannot replace an existing digest path.
- Duplicate publication verifies the existing bytes instead of rewriting the object. Corrupt existing content fails explicitly and is never silently repaired. Linux synchronizes the blob directory before returning success, including after deduplication.
- Reads validate canonical keys, regular-file identity and digest. Traversal, malformed key types, missing content, symlinks/reparse points, directories, FIFOs and corrupt bytes fail. The blob directory itself cannot redirect through a symlink/junction.
- Cleanup owns only one operation's private staging directory. Publication failure, process death and database rollback never remove a final digest. Shared blobs survive another project's failed metadata transaction; unreferenced complete blobs can remain safely.
- Storage failures use the existing `INTEGRITY_FAILED` and `STORAGE_UNAVAILABLE` vocabulary with safe messages. API reads return 500/503 as appropriate. Worker failures retain their storage code and do not publish successful artifacts; benchmark bundle-storage failures no longer become scientific admission failures.
- Benchmark and evidence workspaces have distinct prefixes and retain separate private temporary directories with cleanup on success and Python exceptions. Scientific adapters still consume bytes rather than mutable blob paths.

## Consumer handoff and limits

The two-method `BlobStore` protocol, digest naming, existing blob layout, dependency pins, metadata schema and artifact contracts are unchanged. No data migration is required. Implementations must provide complete immutable publication, verified reads, and safe storage errors. Callers must never delete digest paths to compensate for a metadata failure. `StorageError` remains a `ValueError` subtype for compatibility; catch it before scientific validation failures.

B03 can now consume the storage boundary for exact-byte intake; B05 still owns full scoped lineage resolution, C05 owns evidence ingestion semantics, and D03/D04 own worker termination/recovery. This ticket does not implement object storage, garbage collection, orphan cleanup or protection against privileged filesystem mutation. Crash/power-loss durability is bounded by the filesystem and underlying hardware; native Windows does not exercise directory fsync.

Not rerun for D02: frontend build/browser end-to-end tests, the complete application Compose startup smoke, hosted deployment, backup/restore or live model evaluation. The full application startup remains covered by D01's separate evidence. D02's disposable test containers, network and PostgreSQL volume were removed after verification. Existing documentation and D01 edits were preserved; nothing was committed, pushed or publicly deployed.
