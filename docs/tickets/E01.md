# E01 — Authority and autonomy policy

Status: implemented as a backend policy boundary; runtime integration belongs to dependent tickets.

`workbench.agent_policy` defines strict version 1.0 authority snapshots and canonical SHA-256 policy references, retaining each source policy's revision and digest in the effective snapshot. Server, project, request and assignment constraints intersect: sets intersect, exposure takes the least permissive tier, numeric ceilings take the minimum, permissions require agreement, and mandatory report verification survives narrowing. Empty scope/model sets grant nothing. Goal text and unknown configuration fields cannot define authority.

Defaults grant supported routine tools except scientific replay, with schema/aggregate exposure and bounded resources: 32000 model tokens (including 2000 reserved for finalization), 24 model requests/iterations, 60 tool calls, 8 scientific attempts, 900 active seconds, 2 transient retries, 4 specialist assignments with concurrency 2, delegation depth 1 and one review round. Scientific and provider model allowlists must be configured. Automatic failure recording requires explicit eligibility policy; warning rules refer to trusted rule IDs with conditions and justification. Monetary ceilings intersect when supplied; unknown pricing must not satisfy them in E05.

The action check denies unauthorized tools, cross-project access, out-of-scope materials/artifacts and scientific models. The interruption decision permits routine Autopilot work without approvals, permits bounded inspection before optional plan review, and distinguishes missing material facts from missing authority. E07 resolves facts and consolidates questions; this module does not infer scientific declarations from prose.

B11/B12 must load trusted policy records, check revisions, persist effective snapshots/references and re-intersect changed authority. E03 must resolve ownership before reads/effects and grant newly created artifact IDs transactionally. E05 owns consumption/reservations; E14 owns content classification and filtering. This is not a runnable coordinator or new public API.

Validation: focused policy, provider and bootstrap tests passed (48 checks initially); final regression evidence is recorded in E02. Tests cover narrowing, unknown fields/tools, cross-project IDs, stable references, assignment scope, budget reservations, monetary ceilings, routine actions and review/clarification decisions.
