# B10 — Data and API integration checks

Status: complete; local Linux/PostgreSQL acceptance passed September 20, 2026.

Implementation: PostgreSQL acceptance runner, migrated shared fixtures, expanded
HTTP coverage, and [a reproducible acceptance matrix](../data-integration.md).

The runner requires a reachable PostgreSQL database and all 13 suite families.
It selects PostgreSQL cases explicitly, rejects skipped/xfail/incomplete coverage,
and emits JUnit evidence. Existing migration, lineage, submission, report race,
publication, projection, ledger, scheduler and real receipt-recovery checks form
one command. Ordinary pytest remains available for SQLite development.

Shared runtime fixtures now apply Alembic migrations. Intake and agent HTTP tests
use migrated, isolated SQLite/PostgreSQL fixtures instead of SQLite-only ORM
creation. The new HTTP integration test races four submissions, recreates the API,
replays the accepted request, exercises pause/resume/cancel and event reconnect,
and checks committed run/reservation counts, event payloads and sequence counter,
control revision and retained unknown resource usage. An old intake assertion was
updated for E14's existing error redaction while retaining a separate assertion
that unresolved declarations prevent benchmark admission.

Validation on September 20, 2026 uses base revision
`7a14006c509b1b1601d20dc08ce424671b6fc936` plus this uncommitted B10 change.
`outputs/b10-source-manifest.json` records SHA-256 hashes for the 193 tested
source, contract, dependency and fixture files.

- Initial Linux Python 3.12 / PostgreSQL 16.15 matrix: **169 passed, 184
  deselected, zero skipped**; all 49 schema/OpenAPI files and `pip check` passed.
  This preceded the expanded intake/agent HTTP parameters.
- Final Windows SQLite intake/agent API/lifecycle/worker regression: **44 passed,
  50 skipped**. These skips are unavailable PostgreSQL variants and PostgreSQL
  concurrency checks; they do not count as PostgreSQL acceptance.
- Runner regression: **7 passed**, covering real pytest pass/skip/xfail/failure
  reports, missing PostgreSQL suite coverage, and absent/SQLite database URLs.
- Final expanded Linux Python 3.12.14 / PostgreSQL 16.15 matrix: **184 passed,
  184 deselected, zero skipped** in 313.82 seconds. This includes fresh and
  populated migrations and all added HTTP cases. JUnit: `outputs/b10-results.xml`.
- Supplementary Linux runner/worker/storage/workflow regression: **52 passed,
  2 skipped** in 99.97 seconds. Only the SQLite variants of two PostgreSQL-only
  worker checks skipped; their PostgreSQL counterparts passed. JUnit:
  `outputs/b10-regression.xml`. All **49 schema/OpenAPI files** and `pip check`
  passed after the final runs.

Linux runs use the existing constrained dependency image with current source
mounted read-only, disposable test-container dependency installation and the
isolated `sciml-b10-data` PostgreSQL volume. No application worker competes for
fixture queues. Local logs are `outputs/b10-postgres-final.log` and
`outputs/b10-local-final.log`; final JUnit artifacts are retained under `outputs`.
Existing Starlette/AnyIO deprecation warnings remain.

The source manifest was rechecked after execution and matched every recorded
file. The disposable B10 containers, network and PostgreSQL volume were removed
after saving evidence; unrelated containers were left intact.

No production behavior, schema revision or dependency pin changed. D09 owns
integrating this strict runner into the complete CI gates. Browser, hosted,
live-provider and coordinated restore acceptance were not performed for B10;
this record is not an unqualified release claim.
