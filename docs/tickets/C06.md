# C06 — Failure Memory adapter and retrieval

Status: implemented and locally verified September 19, 2026. Prerequisites C01/B02 are available. Existing uncommitted C01–C05 work was preserved.

## Changed behavior

- `FailureMemory.save` returns the B01 typed `FailureReceipt` with stable external IDs, versioned local request digest and full confirmed upstream record snapshot. The service consumes this receipt while retaining the existing Failure 1.0 artifact format.
- `search` / `search_async` provide bounded project-scoped lexical retrieval through the real upstream API. Typed results identify mapped-project versus no-mapping coverage, live source, limit reach and retrieval limitations. Reads never provision or import; errors are not silently converted to empty matches.
- Remote project matching now uses the workbench ID suffix within the designated lab so local display-name changes do not create a new destination. Ambiguous matching labs/projects fail explicitly.
- Login/cookies/CSRF/logout are shared between imports and searches. Logout is checked and attempted after errors while retaining the primary exception. Imports retain the synchronous file-lock wrapper. No upstream private database/auth/service imports were added.
- The implementation moved to `workbench.failure_memory`, with the existing `adapters.FailureMemory` import kept available. No dependency, public schema or migration changed.

See [the integration guide](../failure-memory-integration.md) for the Python boundary, request digest semantics and mapping/reconciliation limits.

## Handoff and limits

B07/D04 still own durable operation journaling, remote binding and lost-response/commit reconciliation. The typed receipt's digest is currently an internal return value; Failure 1.0 persists its existing ID/snapshot fields. C07 owns Failure 2.0 actor/criterion semantics; E03/B09 own agent tool exposure and authorization/projections.

The current mapping convention requires preserving the upstream lab name and project-ID suffix. Independent removal of those markers cannot be resolved automatically: search reports no mapping and a later import can provision a new destination. This is explicitly documented rather than treated as durable identity recovery. Native record operations remain supported; replay after native edits returns the same record ID with its current snapshot.

Search is lexical with no cursor, up to 200 results and a 10,000-record scope cap. No semantic search or local-snapshot fallback is invented. Callers must supply an already-authorized workbench project; these internal methods are not new unrestricted HTTP endpoints.

Not rerun: the entire backend suite, PostgreSQL/Compose/Linux startup, browser checks, hosted deployment, restore or live-provider evaluation. Nothing was committed, pushed or deployed.
