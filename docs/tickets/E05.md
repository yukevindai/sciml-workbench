# E05 — Atomic budgets and usage

Implemented September 20, 2026 on B11/E01/E02. See [budget accounting](../budgets.md)
for transaction ownership, setup requirements and limits.

## Delivered

- A typed, project-locked reservation/settlement service using B11's durable
  ledgers. Project, run and specialist allowances intersect; retries, concurrent
  work, policy revision and resume do not reset usage. Specialist allocations are
  parent slices, and finalization has a sub-limit inside the aggregate allowance.
- Dispatch records unknown usage before IO. Only its first caller may send;
  duplicate request IDs cannot bind changed intent. Known usage releases unused
  capacity; unknown outcomes retain it. Settlements cannot erase dispatched call,
  tool, scientific or retry counters. Actual overruns are recorded and fence new
  project spending.
- Versioned Decimal pricing snapshots, conservative monetary reservations and
  explicit unknown-cost reporting. Unpriced work cannot pass a strict monetary
  ceiling. No current model price is invented or installed.
- A budgeted wrapper around the real E02 provider, with reviewed concrete-model
  token-bound configuration required before dispatch. Provider IO occurs with no
  checked-out metadata connection. Unrecognized usage fields are rejected as
  unknown usage rather than silently excluded from accounting.
- Atomic budget consumption with scientific job linkage in the B04 project-locked
  submission transaction. Unknown provider receipts and usage entries are included
  in trusted run reconciliation. Detail/history reads show late usage after
  cancellation without rewriting immutable terminal run state.
- Migration `0008` protects reservation intent/lifecycle and refuses populated
  downgrade. No public schema or dependency change.
