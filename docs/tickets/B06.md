# B06 — Run-scoped report capture

Status: capture service implemented and verified on September 19, 2026; persisted run/action integration remains dependent on B11/E03.

B05 was committed and pushed to `origin/main` as `1685958` before this work. B04/B05 are available; the blueprint's B11 prerequisite is not implemented in this checkout. The [capture contract](../report-capture.md) documents the internal interface and the exact remaining integration boundary.

## Changed behavior

- New report requests atomically persist their metadata capture and canonical snapshot digest in the accepted job payload. Existing database immutability guards protect the capture; no migration is required.
- Manual project export freezes project metadata, artifact dependency closure, material bindings and terminal scientific job outcomes at submission. Worker assembly never recaptures later project state.
- Trusted run selections specify roots, producer jobs, selected materials, revision and execution cutoff. Required typed dependencies and producer jobs are included; unrelated active work does not block capture. Explicit artifact/material allowlists apply to the full selection and to replay.
- Submission, artifact publication and material metadata publication share a project barrier. Worker publication locks the project before the claimed job. Selected publication racing capture cannot expose only one half of an artifact/terminal-job commit. Byte publication and scientific execution remain outside the capture lock.
- Same-key replay returns the original capture before checking newer active work. An explicitly authorized retry of a failed report reuses that exact capture. A changed selection/revision/cutoff conflicts.
- Worker preparation verifies the snapshot digest; publication rejects a modified detached capture. Archives include manifest-covered `snapshot.json`. Job projections omit free-form worker errors and private request/worker fields. Prior report artifacts and report-generation provenance are excluded from new captures; report provenance stores the request and digest without embedding another snapshot.
- Pre-B06 jobs without a capture retain their identity on replay but fail execution with `INTEGRITY_FAILED`; they cannot reconstruct a historical snapshot. A new request key creates a new capture. Completed legacy downloads remain supported.

No HTTP schema, environment variable or dependency changed. Existing authenticated manual report routes use the new behavior directly.

## Handoff and limits

B11/E03 must construct selections from persisted authorized run/action records, freeze their capture revision and execution cutoff under the run barrier, coordinate cancellation/amendments, and record the action-to-report-job association. The internal service accepts trusted selections but does not invent or validate missing run records. No public run-report endpoint or agent runtime is enabled, and complete B06 run-ledger integration cannot be claimed before that prerequisite exists.

C08/C09 retain richer scientific archive validation/replay, including future claims, protocols and execution records once their typed producers/resolvers exist. B08 retains broader fenced publication responsibilities. This work introduces no automatic retry policy.

Frontend code is unchanged; frontend build/browser tests, hosted deployment and backup/restore were not rerun. B06 changes remain uncommitted. Only the preceding B05 commit was pushed; nothing was deployed.
