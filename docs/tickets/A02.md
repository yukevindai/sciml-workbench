# A02 — Low-friction project and attachments

Status: implemented and locally verified on September 23, 2026, based on
baseline `674a273`. Implementation is recorded in the commit containing this
handoff. No deployment was performed.

Prerequisites: A01 and B03. This ticket consumes the existing
[attachment API](../intake.md) without changing backend contracts or storage.

## Changed behavior

- Project creation requires only a nonblank name. The research question is
  optional. Name and question survive rejected submissions, structured server
  validation details are readable, and the active project offers direct CSV/PDF
  attachment links. An immediate action guard prevents overlapping submissions;
  context selectors and form inputs are disabled while a mutation is pending.
- CSV declarations start unknown. Upload and permitted inspection remain
  available without citation, license or other source assertions. Selecting a
  different file or project clears the prior draft, preview and retry identity.
  Successful upload selects the returned dataset.
- Synthetic demo declarations can only be applied after hashing a file that
  matches the exact LF repository or CRLF Windows checkout of `examples/demo.csv`.
  A matching filename or column layout is insufficient. Both fingerprints are
  covered by a test against the bundled file.
- Metadata reuse is explicit and limited to datasets in the current project.
  Legacy source fields and known Dataset 2.0 user/source-derived values can be
  copied for review as **new user assertions**, not verified facts. Unknown and
  inferred fields are excluded. Demo metadata is excluded for unrelated files.
  Reuse does not amend original records or create a scientific lineage claim.
- Source JSON is structurally validated before entering form state. Nulls,
  arrays, wrong field types and unsupported fields cannot crash the form.
  Invalid text survives blur and blocks upload. Optional advanced fields include
  target, units and independent unit; the server validates column references.
  An explicitly empty transformations array is preserved and distinguished from
  unknown. Metadata headers escape non-ASCII text without changing its value.
- PDFs now use the B03 attachment endpoint. The original is preserved first;
  extraction is a separate optional action using the material-specific ingestion
  endpoint. Attached originals can be listed and downloaded after reload or a
  failed extraction request. The filename becomes the extraction title, matching
  the attachment API. Custom titles on the legacy endpoint are not used by this UI.
- PDF attachment and extraction retries keep separate request keys while the
  view remains mounted. Acknowledged uploads/extractions disable their action
  buttons. UI copy distinguishes preserved bytes, accepted jobs and successful
  extraction; OCR and automatic verification are not advertised as available.

## Interfaces and configuration

No backend changes, schema regeneration, migrations, dependencies or environment
variables. `parseMaterials` validates lists through the existing generated
material decoder. `AdvancedJson` gains optional draft parsing/validity hooks;
other configuration editors retain their previous behavior. Shared fields expose
`aria-invalid` for visible validation errors. Existing upload limits apply.

The frontend uses the existing project, research-material list/upload/download,
and material-ingestion routes. CSV/PDF byte payloads remain unchanged. Request
keys are retained in memory, not browser storage. No automatic submission retry
or scientific policy assertion was introduced.

## Limits and downstream ownership

Browser tests intercept HTTP responses. This ticket does not establish a new
real-backend scientific workflow or actual PDF extraction result; B03/C05 own
those backend behaviors. No backend suite, hosted acceptance, clean Linux/Node 22
CI, live provider evaluation, or full scientific browser workflow was run.

Draft files/metadata and request identities are not persisted across navigation
or reload. Project creation remains non-idempotent at the existing API. A09 owns
durable retry/recovery and job controls. A03 owns audit configuration/column
selection hardening; A06 owns detailed extracted evidence and citations. A11/A12
own conversational attachments and automated research controls.
