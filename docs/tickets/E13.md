# E13 — Autonomous finalization and execution record

Implemented in the trusted coordinator integration. Apply application migration
`0011` before using it; HTTP/CLI activation requires the reviewed E04 runtime configuration.
No research database was migrated during implementation.

`agent_finalization.py` persists review, capture, export and verification progress
outside advisory checkpoints. An immutable candidate and runtime-version ledger
survive restart. Coordinator versions are retained before model dispatch, including
the source-tree digest, provider/model revision, adapter, runtime, checkpointer,
prompt digest and tool-catalog version. Multiple runtime configurations remain
visible instead of overwriting the original configuration.

Finalization fences amendments and new science. It creates a credential-filtered
execution artifact and an optional independently reviewed claim set. Scientific
artifacts keep their original bytes and upstream software provenance. The frozen
execution cutoff records pending export actions; neither the archive producer nor
its own completion event is recursively captured.

Coordinator report requests now cross this boundary; the provider is not offered
an early `build_report` tool. Requested exports use the existing C08 durable report service. C12 comparison
release and final exposure occur at this trusted boundary, after candidates have
settled; reviewers remain in selection scope. The report contains execution
metadata, runtime-version history, review identity, residual uncertainty and gaps.
It explicitly labels scientific replay as not run.

A transient failed export gets at most one budgeted retry using the identical
frozen capture. C09 archive verification and exact snapshot-digest matching are
required before a report is published as complete. Corruption, failed verification,
budget shortfall, missing review, failed science, incomplete output coverage or
unknown provider usage yields a partial result. Current authority is rechecked
before publication, including after pause/resume or policy narrowing.

Tests execute the installed audit implementation and actual report assembler and
verifier without a subprocess or paid provider. They cover original science and
execution provenance, retry capture identity, immutable candidates, checkpoint-loss
recovery, corrupt archives, amendment fencing, factual fallback, review quarantine
and final comparison exposure. PostgreSQL and Linux process-boundary acceptance
remain environment-dependent; local SQLite coverage is not represented as those
deployment checks.
