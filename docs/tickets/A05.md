# A05 — Benchmark results and protocol context

Status: implemented and locally verified September 24, 2026, based on baseline
`84d45c5`. Prerequisites: A04, C04, C07 and C12. Implementation is recorded in
the commit containing this handoff. No deployment was performed.

## Changed behavior

- The workspace no longer receives benchmark test output while browsing. The
  shell polls a new preview listing in which each benchmark is a
  `BenchmarkPreview`: task card, lineage, status, safe error, sealed-comparison
  bindings, allowlisted validation scalars, validation grid/selected parameters,
  verification scope, current holdout exposure and bundle availability. Test
  metrics, intervals, predictions, bundle keys and digests computed over test
  output are absent, and building the preview records no exposure. Previously
  every 2.5-second poll of `/artifacts` recorded exposure for every benchmark.
- Test scores appear only after an explicit per-run reveal. The confirmation
  states whether this is the first recorded exposure of that exact dataset and
  partition and that later comparisons must be exploratory. The reveal uses the
  existing complete artifact detail, which commits exposure before returning.
  Failed reveals show no output and can be retried. Only the confirmed run is
  revealed. The bundle download is offered after reveal and labeled as
  containing the dataset/predictions and recording raw-data exposure.
- Each run shows exact dataset/split lineage (with a split link), whether it is
  an accepted candidate of a sealed comparison, the frozen task card, units and
  accepted-warning codes with their written justifications, validation metrics,
  the upstream validation grid, and outcome history: its job and any recorded
  unsuccessful outcomes with actor, observation and receipt state.
- Sealed comparisons for the selected dataset show target, features,
  independent unit, candidates, primary metric, selection rule, success
  criterion and the seal-time exposure snapshot, plus current release/exposure
  status read live from the evaluation status route. Status refreshes after a
  reveal. The seal-time snapshot is labeled as not current authorization.
- Metric tables list all supported scalars; absent values read "Not reported",
  a real zero reads "0", and failed runs state that no metrics were produced.
  Execution success is separated from scientific validity.
- The manual task card resets per project/dataset. Exact demo bytes receive
  demo defaults; ordinary datasets start with no target, features, status,
  domain or limitations. A target that is also a feature, duplicate or
  numeric/categorical overlap, stale columns, missing required declarations,
  blank warning justifications, invalid seeds and malformed/unknown-field JSON
  block submission. Missing units only warn, because upstream admission owns
  unit rules and README step 6 deliberately exercises that rejection. Server
  rejection retains the draft. This addresses the target/feature overlap noted
  from remote follow-up `d1f61eb` for the benchmark form.
- `/benchmark?project=<project-id>&benchmark=<benchmark-id>#benchmark-<id>`
  selects the owning dataset/split and focuses the run. Benchmark jobs and the
  read-only agent snapshot link to it. Unknown IDs substitute nothing.

## Interfaces and scope

Backend: `GET /api/v1/projects/{pid}/artifact-previews` (response
`ArtifactPreviews`), `BenchmarkPreview` record contract
(`contracts/records/v1/benchmark_preview.json`), `ReadService.artifact_previews`,
and `evaluation.benchmark_preview`/`protocol_bindings`. Agent scopes are denied
on previews. Failure and claim-set records in the preview listing still expose
their dependencies (`artifact_preview_list`) because they can carry holdout
values. `/artifacts`, artifact detail, downloads and all scientific artifacts are
unchanged. No migration, dependency or environment change. Contract exports
go from 49 to 50 files (one new record; catalog, response and OpenAPI entries updated).

Frontend: the generated `validateArtifactPreviews` decoder rejects a listing
containing a complete benchmark rather than rendering it. Earlier browser suites
now mock `/artifact-previews`. `MetricGrid`/`metricPartition` were removed as
unused. See [evaluation exposure](../evaluation-exposure.md#manual-previews-and-explicit-reveal-a05).

## Limits and downstream ownership

No browser-to-real-backend workflow, PostgreSQL acceptance, live provider,
hosted deployment or Linux startup was run for A05. Reveals are held in page
state; after reload, test scores are withheld again although exposure remains
recorded (a second reveal records another read). The reveal reuses the
`artifact_detail` exposure label rather than a distinct manual-reveal label.
Preview listing is unpaginated like `/artifacts`. Failure recording and receipt
reconciliation UX remain A07; report scope/provenance remain A08; job recovery
remains A09; streaming agent activity remains A11/A12. No scientific metric is
computed in the UI.
