# D08 — Agent and queue diagnostics

Status: implemented with local Linux/PostgreSQL acceptance. No production or
Render operator session was changed, and live deployment monitoring remains
unverified.

`python -m workbench.diagnostics` is a private, read-only operator view with optional
project/run filters and bounded detail lists. It reports safe run/action/job
correlations, queue age, fixed-deadline overruns, lease/checkpoint advancement lag,
unknown model usage, independent worker/model observations, disk capacity and
finite cgroup-v2 memory pressure. Aggregates and alerts cover rows beyond the
detail limit. Paused/input-waiting runs are explicit operator waits; disabled
agents do not produce agent dispatch alarms or imply scientific-worker failure.

Independent scientific/agent heartbeat files separate process observations from
work progress. Provider observations contain only timestamps and fixed outcome
classes. Telemetry IO failures do not abort work or alter leases/budgets. Projection
whitelists omit prompts, private request/outcome bodies, raw errors, checkpoints,
credentials and filesystem paths; the existing secret guard can withhold the
entire snapshot. Alert exit statuses support an operator's existing monitor;
this ticket sends no external notifications and performs no automatic recovery.

See the [diagnostics guide](../diagnostics.md) for thresholds, interpretation,
redaction, scope, limitations and operator commands. No public HTTP endpoint,
frontend change, contract/migration change or new dependency is required. The
existing CI backend regression gate discovers the new tests automatically.

The initial Linux/Python 3.12/PostgreSQL regression covered diagnostics, provider
accounting, agent/scientific execution, durable scheduling and worker process
enforcement: **85 passed, 4 skipped**, with two diagnostics fixture failures.
The fixture attempted to mutate an immutable action intent; it was corrected to
seed private content through the action's initial accepted request. The follow-up
also corrected its missing required tool name. All non-diagnostics regressions
passed; skips are SQLite parameters of PostgreSQL-only cases.

Final September 22, 2026 focused acceptance: **22 passed, no skips**, exercising
both SQLite and PostgreSQL diagnostics, private-content canaries, whole-snapshot
secret withholding, scoped correlation, unknown usage retention, queue/lease and
resource alerts, stale/malformed telemetry, heartbeat progress separation and the
scientific main-loop integration. All **49 schema/OpenAPI files** match, `pip check`
and `git diff --check` passed. These focused cases overlap the initial regression
run and are not additive counts. Disposable containers/network were removed.
No commit, push or deployment was performed.

Operational limits: a recent heartbeat is not proof that the active operation is
progressing. Restored observations can look recent until their window expires.
One heartbeat file per role matches the supported single-worker runtime. Model
observations are historical and do not establish live provider availability or
quality. Cgroup memory describes the diagnostic process's container/service, not
separate Compose worker containers. No CPU or cross-host monitoring is claimed.
