# B05 — Artifact and lineage resolution

Status: implemented; local Windows and Linux/PostgreSQL acceptance passed on September 19, 2026.

Prerequisite: [B03](B03.md). B03/B04 were committed and pushed to `origin/main` as `8a480d7` before this work. The [resolution contract](../artifact-resolution.md) documents the runtime boundary and remaining responsibilities.

## Changed behavior

- Artifact reads, operation admission/replay, worker preparation, checked writes and report capture share a typed, project-scoped resolver. It follows explicit parents and typed references, including references omitted from legacy parent arrays.
- Wrong-kind root selections return `LINEAGE_MISMATCH`; missing/cross-project roots return 404. Missing, foreign, wrong-kind, cyclic or inconsistent stored dependencies return safe `INTEGRITY_FAILED` errors. Iterative traversal has node/depth bounds and enforces transitive allowlists.
- Worker publication binds result identity, parents, typed inputs and operation configuration to the accepted work. A valid same-project artifact cannot be substituted for the accepted input.
- Material reads and report capture validate CSV-to-dataset byte bindings. Artifact and material downloads require authenticated project-bound metadata resolution before accessing storage. Raw digests grant no download authority.
- Evidence downloads preserve the existing default ZIP and support exact original PDF bytes through `?representation=original`. Download filenames sanitize legacy identifiers before placing them in headers.

No migration, dependency or environment change is required. OpenAPI adds only the optional download representation selector. Future registered artifact contracts and source-span references fail closed until their runtime resolvers exist.
