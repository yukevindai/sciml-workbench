# D10 — Release handoff

Status: handoff package implemented and locally verified. **Release acceptance
remains incomplete**: a fresh human-operated live one-request walkthrough,
model quality and hosted acceptance remain open. D09 CI subsequently passed
for candidate `33f7b0a` on September 26; see the
[acceptance follow-up](../release/acceptance-2026-09-26.md).
No hosted deployment, live model call or release has been performed.

The [release handoff](../release-handoff.md) connects clean setup, E16's reviewed
operator/policy path, the one-request demonstration, ordinary recovery and the
coordinated backup/restore procedure. It specifies evidence required from the
reviewer, scope limits and safe matching-version rollback. README now reflects
the implemented agent workspace and labels the old readiness record historical.

`scripts/release_manifest.py` generates/checks the committed compatibility
inventory. It checks frontend/backend/lock/report version agreement, runtime
constraints, Python image agreement and container runtime majors; records the
single migration head, exact scientific Git sources and LF-normalized hashes of
contracts, locks, image definitions and migrations. It does not claim that source
inventory proves installed or deployed compatibility. CI additionally checks
actual package provenance and regenerated schemas.

`scripts/build_example_report.py` computes a real audit, split and baseline from
the bundled synthetic CSV, builds/verifies a report and requires matching
scientific replay. It uses installed public adapters, never a test/mock scientific
result, database, provider or Failure Memory import. The checked-in example ZIP
and external verification receipt are in `examples/release`. CI generates and
uploads a fresh example and its revision-specific evidence. Freshly generated
IDs/timestamps mean report bytes are not expected to equal the supplied example.
