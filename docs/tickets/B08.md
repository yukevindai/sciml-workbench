# B08 — Fenced result publication

Implemented September 19, 2026 on the existing B04/B05/D03 foundation and current B07 working tree. See the [publication contract](../publication.md).

## Changed behavior

- Centralized publication in `workbench.publication`, retained the worker import for internal compatibility, and kept scientific execution in D03's bounded subprocesses.
- Output/source blob references must resolve to verified immutable bytes before acquiring metadata locks. A successful benchmark requires a bundle; missing/corrupt files reject publication without exposing a result.
- Publication copies its inputs, locks project before job, checks the original token/worker/running state and deadline after lock waits, reloads authoritative immutable inputs, and rejects detached metadata substitution. Report capture, typed lineage/configuration and B07 receipt checks remain enforced.
- Artifact, provenance, job result link/terminal state and receipt artifact linkage commit together. Flush/commit failure exposes none of that outcome. Previously confirmed external receipts and durable immutable files remain intact.
- Added a trusted, project-scoped cancellation fence that advances the matching claim token and records operational `RUN_CANCELLED`. Cancellation cannot overwrite a completed/replaced claim, and late results/errors cannot overwrite a committed cancellation. Worker stop signals are rechecked after locks and before terminalization.
- No new migration or HTTP schema: B07's `0004` remains required. Run ownership, control generations, cancellation endpoints, shared-job detachment and process termination remain B11/B12/D12 work.

## Handoff

Callers of `publish_result` must supply `store=` for blob-backed artifacts. Controllers must authorize the project and establish sole job ownership before calling `fence_cancelled` in their control transaction; acknowledge effective cancellation only after commit. This primitive does not implement the agent control plane or cancel queued jobs.

Publication's conditional terminal update is its decision point within the transaction; committed results remain authoritative. Cancellation racing behind that transaction preserves completed work. Cancellation that commits first prevents later scientific publication without pretending to undo an upstream import.

Verification used the disposable `sciml-b08-publication` Compose project; its containers, network and database volume were removed afterward. Included alongside B07/B09 in the implementation commit. No application database, frontend or deployment was changed. The previously observed, unchanged cluster-split exact-diagnostics mismatch is outside this ticket's selected acceptance suites.
