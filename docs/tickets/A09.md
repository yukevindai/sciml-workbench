# A09 — Scientific job recovery UI

Status: implemented and locally verified September 24, 2026, based on baseline
`7b21dd6`. Prerequisites: A03, B09, D04 and E08. Implementation is recorded in
the commit containing this handoff. No deployment was performed.

## Changed behavior

- **Scoped job reads.** The workspace now reads jobs from the B09
  `job-index` (newest first, following up to five pages of 100) instead of the
  unbounded legacy `/jobs` list. Each job carries its safe error code, external
  receipt, agent-run links and D04 recovery decision. When older jobs exist
  beyond the loaded pages, the list says so and adds nothing in their place.
- **Polling, backoff and terminal refresh.** Jobs are polled every 2.5 s while
  work is queued or running, every 10 s when idle and every 30 s in a hidden
  tab. When the tab becomes visible, jobs are polled immediately. After a failed
  read the delay doubles (5 s, 10 s, 20 s … capped at 60 s) and resets on
  success. Artifact previews are no longer re-read on every tick. They are read
  when any job appears or changes state, result, receipt or recovery status
  (including reaching a terminal state), after a submission, on **Retry
  loading**, and at least every 30 s for work created outside jobs. The job
  snapshot advances only together with its artifacts, so a failed artifact read
  is retried.
- **Outages.** Earlier jobs and results stay visible. The alert gives the time
  of the last successful read and of the next automatic attempt. **Retry
  loading** polls immediately.
- **Retained request keys.** Audit, split, benchmark, Failure Memory and report
  submissions go through one helper (`lib/submissions.ts`):
  - The key and exact body are written to this browser's local storage before
    sending.
  - They are kept until the server accepts the request or refuses it outright
    (any 4xx except 408/429).
  - A network error, timeout (60 s), 5xx, 408/429, or a 2xx body that fails
    validation leaves the request **unconfirmed**. Submitting the same kind and
    payload again, including after a reload, reuses the key and gets back the
    original job. Different inputs are a new request.
  - Job activity lists unconfirmed submissions with **Resend with the same
    key** and **Forget**. Nothing is resent automatically: loading or
    reloading the page never submits work.
  - A07's per-draft and A08's per-export in-memory keys now use this helper, so
    they also survive a reload.
- **Job activity** was rebuilt for recovery. Each job shows:
  - Timestamps, including the deadline of a running job.
  - For failed jobs: the error code and safe error.
  - The recorded result. A failed job with a result links to it, with a note
    that the artifact records an unsuccessful outcome. A failed job without one
    says it published no result artifact.
  - A link to the Failure 2.0 record whose `source_job_id` is this job.
  - The receipt state of Failure Memory imports.
  - "New attempt of" and "Retried as" links between an original and its retry.
    The original keeps its failed outcome.
  - Recovery status, one of: not retried automatically (ineligible), scheduled
    (attempts used and next time), in progress, recovered, or stopped (last
    error).
  - Linked agent runs, with action and ownership (owned / shared / detached).
    With no link it reads "No agent run is linked", which does not claim the
    job was manual.

  The list can be filtered (all / queued or running / failed). It shows 10 jobs
  and expands on request. Each row has the anchor `#job-<id>`.
- **Busy states.** Reads that hold a poll slot time out after 30 s and
  submissions after 60 s, so `act()` always releases its busy state. A
  submission failure during an outage leaves the controls enabled, with the
  retained key available.

## Interfaces and scope

`JobDetail` gains two fields, populated for manual reads only:
- `run_links`: `run_id`, `action_id` and `ownership`, from `run_job_links`.
- `recovery`: state, eligibility, attempts, max attempts, `retry_job_id`,
  `next_attempt_at` (pending only) and last safe error code, from
  `job_recoveries`.

Agent-scoped reads return `[]` and `null`. Lease tokens, policy bodies and
history text are not exposed. `GET /job-index` accepts `order=asc|desc`
(default `asc`, unchanged). Cursors are bound to their order, so an ascending
cursor is rejected on a descending read. Contract exports stay at 54 files
(`job_detail`, `job_page`, catalog, response and OpenAPI entries changed). There
is no migration or environment change. The legacy `/jobs` route is unchanged
and no longer read by the browser.

Browser `Job` is now the generated `JobDetail`. POST responses are still
decoded as `LegacyJobResponse`. `api()` throws `ApiError` with the HTTP status
and accepts an optional timeout.

## Limits and downstream ownership

No browser-to-real-backend workflow, PostgreSQL acceptance, live provider,
hosted deployment or Linux startup was run for A09. `private-access` and
`workflow.spec` were not rerun.

Retained keys live in one browser's local storage (in-memory if storage is
unavailable). They do not follow a researcher to another browser. Up to 20 are
kept per project, with no expiry. Binary uploads (CSV and PDF bodies) still use
their existing in-memory keys, because their bytes are not persisted, so a
reload during an upload loses that key. Project creation remains
non-idempotent.

Only the newest 500 jobs are loaded. An active job older than that would not
disable dependent controls, although server admission still rejects conflicting
work. Agent runs appear as IDs; there is no run page to link to yet (A11/A12).
The UI offers no manual "retry failed job". Explicit retries remain an internal
B04/D04 interface, and automatic recovery follows D04 policy. Streaming,
pause/resume/cancel controls and reconnect by event sequence remain A11/A12.
Hosted acceptance remains A10.
