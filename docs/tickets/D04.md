# D04 — Interrupted scientific and import recovery

Implemented on the D03/B07/B08/C06/C07 foundation. See the
[recovery contract](../recovery.md) for policy, scheduling and operational limits.

## Delivered

- Migration `0007` records recovery policy, leases, attempt history, backoff and
  scientific retry linkage without changing original jobs or external identities.
- The scientific worker automatically discovers failed jobs and performs one
  eligible recovery per loop. Expired D03 claims become eligible after sweeping.
- A transient manual scientific failure can queue one linked retry with identical
  accepted inputs. Deterministic rejection, cancellation, prior retries, agent
  ownership and sealed evaluation membership cannot trigger this manual policy.
- Interrupted imports reconcile the exact original journaled request. Confirmed
  receipts publish missing Failure 1.0/2.0 artifacts with authoritative input
  validation, project locking and a recovery lease fence. Artifact, provenance,
  receipt linkage and recovery completion commit together. Original failures stay
  failed and unknown receipts never imply scientific success.
- Crashes consume the recorded three-attempt recovery limit; restart never resets
  it. Concurrent discovery/claiming cannot duplicate the automatic scientific
  retry. The API reserves the internal recovery request-key namespace.

## Handoff

Apply migration `0007` before worker startup. There is no new frontend, HTTP
contract, dependency, hosted deployment or provider call. D11/D12/E08 retain
agent-budget/control-aware recovery and evaluation-linked retry authority. D04
does not garbage-collect abandoned workspaces or implement backup/restore.
