Status: implemented; focused local acceptance checks passed on September 19, 2026. Clean CI and release acceptance remain separate gates.

Implementation commit: `c2d36a194a81df600ff4b3492c7f6bfa334f1a51`.

Baseline: `efea1532fb7edf7ec498ddde2a431eb0a79f6c60`. This handoff follows section 23.2 of the [implementation blueprint](../../sciml-workbench-mvp-design.md). See [contract ownership and compatibility rules](../contracts.md) for the consumer interface.

## Changed behavior and interfaces

- Published strict Pydantic contracts for Dataset 2.0, Failure 2.0, evidence and metric references, claim sets, evaluation protocols, research plans/runs, assignments, questions, tool envelopes, usage, events, and agent execution records.
- Added an explicit artifact kind/version registry covering 13 pairs. The eight legacy 1.0 schemas retain their validation meaning and remain readable without rewriting stored artifacts. New readers reject missing or unsupported version discriminators.
- Dataset declarations distinguish unknown, user-supplied, source-derived, and inferred values. Failure actors distinguish human and agent attribution. Cross-field validation rejects inconsistent declarations, ambiguous actors, and invalid scientific observations.
- Published deterministic JSON Schema and OpenAPI exports, generated TypeScript types, and precompiled browser response validators. Existing frontend API calls now decode responses; opaque upstream dictionaries are checked before display.
- Added response models to existing API routes and a stable error vocabulary with server-generated request IDs. Existing error strings and validation-detail arrays remain compatible. Future contract components do not advertise new routes.
- Added non-mutating schema and client generation checks to CI, frozen legacy fixtures/schema digests, and backend/frontend contract tests.

## Migrations and configuration

No database migration, environment variable, provider configuration, or deployment change is required. The npm lockfile includes pinned schema generation and validation dependencies; use `npm ci` in `frontend` when updating a checkout.

Current manual API writers, persistence consumers, and report/replay still use legacy artifacts. Before emitting new versions, B03 and its consumers must integrate the versioned reader across their storage, adapters, reports, and frontend paths. The archive manifest remains 1.0; C08/C09 own its later expansion. Existing data is not migrated or backfilled by B01.

## Consumer handoff and limits

B01 supplies the prerequisite interfaces for B02, E01, D01, C01, and A01. No dependent ticket is marked complete by this handoff.

- B02: preserve immutable legacy JSON while adding relational invariants and migrations.
- E01: define policy intersection, authority semantics, and defaults; the published policy references do not enforce authorization.
- D01/C01: establish the constrained runtime and verify pinned public scientific capabilities.
- A01: consume generated types and runtime decoders while building the research shell.

Schema validation establishes structure and selected cross-field consistency. It does not prove source truth, grounding, project ownership, prior criterion declaration, or permission to execute tools. Python semantic checks are authoritative; browser validators do not duplicate every cross-field validator. C11/C12 and subsequent B/E services must enforce those boundaries.

The implementation and this handoff are local commits; no push or deployment was performed. Earlier planning/documentation edits and the pre-existing Render setup edit remain outside the B01 implementation commit.
