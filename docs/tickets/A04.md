# A04 — Split inspection and visualization

Status: implemented and locally verified September 24, 2026, based on baseline
`b56bc2a`. Prerequisites: A03, C03 and B05. Implementation is recorded in the
commit containing this handoff. No deployment was performed.

## Changed behavior

- Direct project/split links override saved dataset selection and focus the exact
  result. Stored partitions can be selected individually. Audit and split jobs
  and read-only agent result snapshots link to their respective inspection views.
- Inspection shows the exact recorded dataset/audit IDs, original CSV hash and
  source audit link. Parent/typed-reference mismatches and missing dependencies
  stay visible. Another dataset's audit never supplies the recorded lineage or
  becomes an eligible manual submission input.
- Requested and effective configuration are separate. Actual counts include all
  four partition labels, including zero counts and exclusions. Percentages use
  the complete stored assignment count as their explicit denominator.
- Requested proportions and actual-count charts have table alternatives. The
  decorative row grid labels its 400-row preview limit; an accessible 50-row
  paginated table and JSON download expose every assignment. Row positions are
  zero-based and distinguished from original row-ID values. Downloads retain
  the complete assignment array and project/split/dataset/audit identifiers.
- Readable diagnostics include upstream warnings, generalization claims and
  limits, checks not configured, pairwise duplicate/group overlap and findings
  with suggestions/row references. Full boundaries/distribution diagnostics and
  complete artifacts remain inspectable. Missing values are not invented zeros.
  Inconsistent assignment/position/count reports produce a visible warning.
- Excluded rows remain in the original dataset and are not silently discarded.
  The view separates completed split execution from benchmark admission,
  scientific validity and test-metric exposure authority.
- Manual configuration resets on dataset changes. Exact demo bytes receive demo
  defaults; ordinary data has empty column choices and no target. The source
  audit is visible and selectable from matching dataset lineage only. Invalid
  JSON, stale common columns, invalid shares and invalid seeds block submission;
  server rejection retains the draft and advanced fields. Zero validation share
  is allowed for supported two-way splits. Nine base strategies are suggested;
  advanced semantics remain upstream-owned.

## Interfaces and scope

No backend, public schema, dependency, migration or environment changes. The
existing manual split endpoint, artifact/job reads and generated ResearchRun
validator are reused. A03's agent snapshot component is shared with split
inspection; its first-50-run limit, explicit refresh and independent failure
handling remain unchanged. It does not infer an artifact's human/agent origin.

Direct URL:
`/split-designer?project=<project-id>&split=<split-id>#split-<split-id>`.
Full assignment download is generated locally from the already validated artifact
response; it does not change or regenerate the underlying scientific result.
The UI's presentation consistency checks do not replace B05/C03 authorization,
publication or exchange validation.

## Limits and downstream ownership

Browser tests intercept HTTP; real Python execution is verified independently.
No browser-to-real-backend workflow, full backend suite, PostgreSQL acceptance,
live provider, hosted deployment or Linux startup was run for A04.

Manual drafts remain local to the mounted dataset form. Agent event streams,
controls and durable recovery remain A09/A11/A12 responsibilities. Benchmark
protocol context and test exposure UI remain A05 work. General provenance/report
inspection remains A08 work. Full diagnostic JSON is available for sections not
projected into dedicated tables; no scientific algorithm is implemented in UI.
