# A08 — Provenance and completed reports

Status: implemented and locally verified September 24, 2026, based on baseline
`c8dc069`. Prerequisites: A04, A06, A07, B05, C08 and E13. Implementation is
recorded in the commit containing this handoff. No deployment was performed.

## Changed behavior

- **Lineage table and graph.** Provenance now lists every artifact with its
  kind, readable label, full ID, creation time, "depends on" (recorded parents)
  and "used by". Each entry links to its inspection view (audit, split,
  benchmark, evidence, claims, failure, report). A layered graph is drawn for up
  to 60 artifacts, or for the neighbourhood of a focused artifact (everything it
  depends on and everything derived from it). The graph is decorative; the
  table is the complete accessible equivalent. Before A08 this view showed only
  a flat list of activity records with shortened IDs.
- **Broken references stay visible.** A parent or activity input/output that
  does not resolve in the project listing is counted in an alert. It appears as
  a red "Missing reference" row and a dashed graph node, and as "Missing: … (not
  in this project listing)" wherever it is referenced. Nothing is dropped or
  substituted. A recorded cycle is reported, and nodes are still laid out.
- **Report inspection.** Each archive card shows download, current structural
  verification (verified with time, or failed with its reason) and scientific
  replay, which is always "Not run": the workbench never runs `workbench.replay`.
  Verified archives also list:
  - The frozen scope: project-wide manual export, or run-scoped with run ID,
    capture revision, event cutoff and the "pending" export status at capture.
  - Every frozen input, with links to current artifacts. Inputs no longer in
    the listing are shown as such.
  - Settled job counts, with failed jobs and their error codes kept visible.
  - Attachments, Python/platform, scientific software and upstream source pins.
  - For agent-run exports: each execution record's provider/model/revision,
    prompt and tool catalog, runtime/checkpointer/SDK, workbench revision,
    policy, state at cutoff and pending actions. Finalization review status,
    runtime-configuration count and recorded gaps are shown too. A manual
    project export says it names no agent versions.

  A failed check shows no contents. The three newest archives are checked
  automatically; older ones are checked on request. Read failures are explicit
  and can be retried.
- **Manual export.** It keeps one request key until accepted, so double clicks
  and retries after a failed response resolve to one job. It is disabled while
  other jobs run or an export is in progress. The export job list shows failed
  exports as producing no archive. Report jobs link to their archive.
  `/report?project=<p>&report=<id>#report-<id>` and
  `/provenance?project=<p>&artifact=<id>` focus an archive or artifact. Unknown
  IDs substitute nothing.

## Fixed defect

`AgentExecutionRecord` (E13 `agent_execution`) was missing from the
`IntakeArtifact` and `ArtifactPreview` response unions. After an agent run
finalized, `/artifacts` and `/artifact-previews` failed response validation
with a 500, so the whole workspace could not load that project. I confirmed
this by temporarily reverting the union change: the new agent-run test then
fails with 500. Both unions now include the record, and the frontend
`kinds()` map knows `agent_execution`.

## Interfaces and scope

New read-only route: `GET /api/v1/projects/{p}/reports/{r}/summary` →
`ReportSummary` (`workbench/report_inspection.py`). It returns identities, not
values, and records no exposure. Agent scopes are denied. Storage outages
return errors; digest, structure and inventory failures return a failed
verification with no contents. Contract exports go from 53 to 54 files (one
record plus catalog, response and OpenAPI entries, including the extended
unions). There is no migration or environment change. Run-scoped report
selection stays a trusted internal interface (B06). The UI cannot choose a
report scope; it shows the scope each archive froze.

For local verification, the declared and pinned `langgraph` and
`langgraph-checkpoint-postgres` packages were installed into the ignored
`outputs/c01-venv` with `uv pip install -c backend/constraints.txt`. They were
missing, which kept the agent-finalization suites from importing.

## Limits and downstream ownership

No browser-to-real-backend workflow, PostgreSQL acceptance, live provider,
hosted deployment or Linux startup was run for A08. `private-access` and
`workflow.spec` were not rerun. Verification is structural and runs on every
summary request. For large archives this is proportionate to archive size (up
to the verifier's 512 MiB expanded budget) and is not cached. Structural
verification proves internal consistency, not authorship. Scientific replay
remains a CLI step whose outcome is not recorded in the workbench. The lineage
graph uses a simple layered layout without edge-crossing minimization.
Agent-run automatic export status (E13 finalization state) is shown only
through the archive it produced; runs whose export failed are visible through
the run and job surfaces, not here. Job recovery UI remains A09; stream and
controls remain A11/A12; hosted acceptance remains A10.
