# D01 — Environment and process bootstrap

Status: implemented; clean installation, Linux Compose startup and focused runtime acceptance passed on September 19, 2026.

Prerequisite: [B01](B01.md). Tested working tree based on `36a68ba42f6d23cc00b5f55ed244b0164a33842b`; no implementation commit or push was made in this task. See the [runtime setup guide](../runtime-setup.md) for the configuration contract and repeatable commands.

## Changed behavior

- Compose retains independently started API and scientific worker processes and adds an opt-in `agent-worker` service with private model configuration. The reserved entry point exits clearly when disabled or unavailable; E02/B11/D11 still own the actual provider, persistence and scheduler. There is no idle process pretending to be a working agent.
- A shared `python -m workbench.setup` entry point validates configuration before migrating metadata and provisioning Failure Memory through its public CLI. Compose gates setup on PostgreSQL health, API/worker on successful setup, and web on API health. The hosted launcher reuses this setup path.
- Backend configuration requires an explicit database URL, rejects blank/placeholder credentials and invalid limits, and reports environment variable names without their values. `python -m workbench.config` provides an offline preflight. Database URLs and provider keys are omitted/redacted in settings representations.
- Provider credentials are supplied only to the reserved agent service in Compose. A separate frontend environment example contains only Next.js server proxy/login settings. Docker excludes private environment files, virtual environments and generated outputs from build context. The web server still needs the existing API bearer token; database, upstream and model credentials are absent, and no bearer token is sent to the browser.
- The supervised runtime explicitly requires Linux containers or Linux/WSL. Native Windows fails before setup/child creation with a useful instruction; its development tests remain supported. Linux process-group peer shutdown is exercised by the hosting test.
- The clean Python 3.12 run exposed Python-version-dependent default HTTP descriptions for 413/422. OpenAPI generation now preserves the existing B01 descriptions and key ordering across Python 3.12/3.13; no generated contract or public schema was changed.
- CI now checks dependency compatibility, offline preflight, resolved Compose environment allowlists and startup ordering, setup replay with writers stopped, and the unavailable-agent exit/redaction boundary.
