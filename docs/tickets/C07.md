Implemented September 19, 2026. See [outcome admission and compatibility](../unsuccessful-outcomes.md).

## Result

Added the trusted `SubmissionService.submit_outcome` entry point with separately supplied actor context. Failure 2.0 distinguishes exact execution errors, missed predeclared criteria and human researcher assessments; agents cannot assert researcher judgments. Criteria must match a protocol persisted before benchmark submission, its exact configuration and dataset/split fingerprints, and a real stored numeric metric. Missing values remain absent. Hypotheses remain distinct from observations.

Supported terminal benchmark runtime failures without results receive deterministic failed snapshots with empty results and no bundle. Their original source jobs remain unchanged. Cancellation, provider outage and policy denial cannot be relabeled as supported execution errors. Unsupported or fabricated observations roll back admission, including any pending runtime snapshot.

Imports use the B07 durable identity/body and confirmed receipt. Publication retains B08 claim fencing and atomic artifact/provenance/job/receipt linkage, with authoritative revalidation. Unknown imports cannot publish confirmed outcomes. Runtime graph resolution, HTTP/browser reads and report capture support the new records and preserve source jobs, protocol references, schemas, attribution and hypothesis labels. Legacy Failure 1.0 remains unchanged.
