# C03 — SciSplit and exchange integrity

Status: implemented and locally verified September 19, 2026. Prerequisite C02 is available. Existing uncommitted C01/C02 changes were preserved.

## Changed behavior

- Split execution checks exact dataset bytes/digest, row count and column order. The real public SciSplit result is retained, including full diagnostics/findings and excluded rows; its positions, counts and configuration are verified.
- Worker publication checks one supported assignment per original row and a complete, disjoint, in-range integer positional cover. Missing/repeated/misaligned positions and inconsistent diagnostic counts/configuration fail before artifact publication.
- Benchmark exchange checks request/dataset/split identity, dataset/project ownership, raw-byte binding and nonblank unique row IDs. Exact string IDs are paired with assignments using strict zip. Short or long assignments cannot silently truncate the exchange.
- Excluded rows remain explicit. A real excluded-row fixture reaches the pinned ChemE admission gate, which rejects it; no data is silently curated to make admission succeed.
- Replay validates split coverage and dataset binding before recomputing assignments. Integrity failures during benchmark execution propagate without publishing a misleading scientific failure result. Unsupported strategy/molecular capability and invalid scientific configuration have distinct error codes.

See [the integrity guide](../split-integrity.md) for the boundary and compatibility details. No split algorithm, private upstream import, dependency pin, public schema or database migration was added or changed. The C01 benchmark fixture now supplies actual Split lineage and request IDs required by the hardened adapter.

## Handoff and limits

C04 can consume the complete validated exchange. A04 owns richer split UI/visualization; full assignments and diagnostics are already available in the artifact response. C09 owns general archive closure/path/schema hardening and numerical replay equivalence. C12 still owns benchmark evaluation exposure; successful splitting is not scientific acceptance or permission to reveal test metrics.

Existing Split 1.0 artifacts remain readable, but malformed historical records cannot be successfully exchanged/replayed merely because their outer schema parses. No original upload is rewritten. The base environment still lacks RDKit; this work does not enable scaffold/molecular splitting there.

Not rerun: the entire backend suite, PostgreSQL/Compose/Linux startup, browser checks, hosted CI/deployment, restore or live-provider evaluation. No commit, push or deployment was performed.
