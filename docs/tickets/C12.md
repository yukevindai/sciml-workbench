# C12 — Evaluation protocol and exposure boundary

Implemented and locally verified September 19, 2026, alongside C11 and the existing C07 working tree. See [evaluation and exposure](../evaluation-exposure.md).

## Result

Sealed comparisons preserve candidate requests, target/features, dataset/split fingerprints, baseline models/seeds and declared criteria. Agent submissions require accepted candidates and trusted run/action scope. Release waits for all candidates to settle and prevents subsequent candidate submission. Unsupported validation-only selection fails with an explicit limitation; workbench does not replace upstream science or claim separately executed final testing.

Complete upstream output stays server-side. Selection agents receive only scoped validation scalar projections; test scalars require a released comparison and trusted final-purpose scope. Raw artifacts, data, predictions, bundles, reports and untyped live Failure Memory retrieval are blocked for agents. C11 metric/claim reads use the same boundary. Job/index projections contain scoped metadata rather than arbitrary result/error text.

Manual lists/details/downloads record exposure, and HTTP commits it before returning content. Legacy/human Failure Memory imports record conservative exposure before upstream IO. Raw datasets and live manual failure retrieval use broad dataset exposure. Exact-byte equivalent uploads and identical partition assignments retain history across new IDs/runs. Prior unknown or exposed histories require an explicit exploratory comparison. Reports freeze exposure metadata with their scientific capture.

Migration **0005** adds immutable named anchors, sealed evaluation rows, accepted candidate bindings and retained exposure events. Historical datasets receive `legacy_unknown` markers, and populated ledgers cannot be downgraded away. Capabilities are now **1.1**; typed evaluation/status read projections and the protected current-status route are included.
