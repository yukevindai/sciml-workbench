# A03 — Audit inspection and manual fallback

Status: implemented and locally verified on September 23, 2026, based on
baseline `455b2b6`. Implementation is recorded in the commit containing this
handoff. No deployment was performed.
Prerequisites: A02, C02 and B04.

## Changed behavior

- Audit inspection exposes actual upstream finding codes, original severity,
  suggestions, columns, zero-based row positions and details. Long row lists
  show the first 20 with a disclosure containing all positions. Unknown severity
  is counted separately; malformed findings show an explicit unavailable state.
  Complete artifacts remain inspectable.
- Requested column/configuration choices and effective upstream defaults are
  separate. Check coverage includes rows, executed checks and skipped reasons.
  Completed execution, error-severity findings and empty findings all retain an
  explicit statement that scientific acceptance has not been assessed.
- Dataset lineage resolves the audit's declared dataset and parent in the same
  project. Valid lineage shows filename, original CSV SHA-256 and download.
  Broken lineage does not borrow the current selection's source information.
- Direct project/audit links override persisted selection and focus the result.
  Audit job results and linked agent results open that route. Unavailable
  projects/audits produce explicit messages; malformed links return 404.
- Manual configuration resets on dataset changes, even when two datasets have
  identical columns. Ordinary uploads have no assumed target or columns; only
  exact bundled demo fingerprints receive demo configuration. Guided target
  changes remove that column from features. Invalid JSON, stale common column
  references and target/feature overlap block submission. Advanced options are
  preserved, and server rejection retains the draft.
- Agent activity is a separately loaded, refreshable, read-only snapshot of the
  first 50 project runs, filtered by the selected dataset's input/result links.
  Errors do not disable manual audit. The UI does not infer an artifact's actor
  or claim the snapshot is complete history, chronological recency or live state.

## Interfaces

No backend, migration, dependency or generated-contract changes. The existing
manual audit endpoint and ResearchRun list/validator are reused. Direct URL:
`/dataset-audit?project=<project-id>&audit=<audit-id>#audit-<audit-id>`.
`parseResearchRuns` adds a named wrapper around the existing generated validator.
Shared inputs gain an optional empty selection; panels gain optional focusability.

See the [audit integration guide](../audit-integration.md) for the scientific
boundary. UI checks protect editable fields; they do not duplicate the auditor's
scientific configuration validation or admission policy.

## Limits and downstream ownership

The snapshot does not implement conversational orchestration, live events,
approval controls or durable retry/recovery. Those remain A09/A11/A12 work.
Manual draft/configuration state is local to the mounted dataset form. The
existing submission/retry behavior is unchanged.

No live provider, hosted deployment, PostgreSQL acceptance, complete backend
suite or browser-to-real-backend scientific workflow was run. No scientific
validity claim is made by these integration and presentation checks.
