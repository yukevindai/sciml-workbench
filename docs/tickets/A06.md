# A06 — Evidence and claim inspection

Status: implemented and locally verified September 24, 2026, based on baseline
`fa59a57`. Prerequisites: A02, C05, B04 and C11. Implementation is recorded in
the commit containing this handoff. No deployment was performed.

## Changed behavior

- Each ingested document shows **supplied metadata** separately from content
  **derived from the PDF**. Supplied metadata has an "Unverified" label and notes
  that the manual flow uses the attachment filename as its title. The derived
  section shows the original SHA-256, page count, how many pages have a text
  layer, the extraction method (PDFium text layer, no OCR) and software
  versions. Before A06 the view showed only a title, a page count and raw JSON.
- The original PDF and the complete source bundle download separately
  (`representation=original` / `bundle`). The attachment list and its original
  download are unchanged from A02.
- A page table lists every upstream page with its text-layer availability, size
  and text digest. **Show text** loads one page's exact text on request, with
  line breaks and spacing unchanged. A page without a text layer says so and
  shows nothing. A document with no text on any page, or on only some pages,
  gets a warning that OCR is not available. A loaded page whose digest differs
  from the ingestion record gets an error. Malformed ingestion records are
  listed as issues rather than filled in.
- Claim sets list each claim's statement, category (computed result,
  source-supported, interpretation, hypothesis), reference-check status and
  issues, and semantic-review status. "Support not reviewed" is always shown
  separately from "References verified". Population, uncertainty, limitations
  and the split link are shown too. Metric references list benchmark, JSON
  pointer, partition, value and units. A real zero reads "0". A missing
  benchmark is labeled unavailable.
- **Open citation** fetches the stored claim's own reference from the server,
  which rechecks it against the retained bytes. The view highlights the exact
  excerpt with up to 320 unmodified code points of context on each side, and
  labels the page and code-point offsets. A citation with no page anchor is
  labeled as whole-document text, and no page is derived for it. **Show on page
  N** focuses the source document, loads that page and highlights the span, but
  only if the page still contains the verified excerpt at that locator. Offsets
  are counted in code points, not UTF-16 units. A failed verification shows an
  error and no text.
- Named anchors (C11 `evidence_spans`) are listed under their source document.
  Each one is reverified when opened.
- `/evidence?project=<p>&evidence=<id>#evidence-<id>` focuses a document and
  `&claim_set=<id>#claim-set-<id>` focuses a claim set. Unknown IDs show an
  error and substitute nothing. Succeeded evidence jobs link to their document.

## Interfaces and scope

The backend adds four read-only, project-scoped routes. All of them reverify
through C11 `evidence_text` on every call and record no holdout exposure:

- `GET /api/v1/projects/{p}/evidence/{e}/pages/{n}` → `EvidencePageText`
- `GET /api/v1/projects/{p}/claim-sets/{c}/claims/{claim}/source-references/{i}` → `EvidenceSpanView`
- `GET /api/v1/projects/{p}/evidence-spans` → `EvidenceAnchor[]` (no text)
- `GET /api/v1/projects/{p}/evidence-spans/{s}` → `EvidenceSpanView`

The helpers `references.checked_span`, `span_context`, `page_text`,
`claim_source_span`, `evidence_anchors` and `registered_span_context` are new.
`verify_span` behaves as before. Contract exports go from 50 to 53 files: three
records, plus catalog, response and OpenAPI entries. There is no migration,
dependency or environment change, and no new write path. Details are in
[evidence references](../evidence-references.md#manual-inspection-routes-a06)
and [read projections](../read-projections.md).

On the frontend, the generated `EvidencePageText`, `EvidenceSpanView` and
`EvidenceAnchors` validators decode every response. The UI also checks that a
returned span matches the claim's reference (source, digest, locator and page)
before rendering it. The new files are `lib/evidence.ts`,
`components/evidence-inspection.tsx` and `components/claim-inspection.tsx`.

A06 also fixes a one-byte Latin-1 `²` that A05 left in
`docs/evaluation-exposure.md` (it was invalid UTF-8).

## Limits and downstream ownership

No browser-to-real-backend workflow, PostgreSQL acceptance, live provider,
hosted deployment or Linux startup was run for A06. `private-access` and
`workflow.spec` were not rerun. There is still no manual way to create
references, anchors or claim sets: they come from C11 services and agent runs,
and E11 owns semantic review. A citation's context is bounded to 320 code
points on each side. Full pages load one at a time up to 1,000,000 code points.
Whole-document citations are never mapped to a page. The claim listing still
records exposure for claim-set dependencies, as in A05. Loaded pages and opened
citations live in page state, so a reload closes them. Source declarations
bound to CSV datasets are not shown here. Provenance and report scope remain
A08. Failure receipts remain A07.
