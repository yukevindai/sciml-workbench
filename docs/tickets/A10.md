# A10 — Browser and hosted acceptance

Status: **local** browser acceptance implemented and passed September 25, 2026,
based on baseline `43b3171` (A12). **Hosted acceptance was not run.** By
decision, no Render deployment was made and no live model provider was called.
Prerequisites: A08, A09, A12, C09, D06 and E13.

## What was accepted

The real stack ran on Docker Desktop (Linux/arm64) as Compose project `a10`,
with no request interception:
- PostgreSQL 16;
- migrations and setup (including Failure Memory provisioning);
- the API;
- the scientific worker;
- the Next.js web service behind the password gate.

The browser was installed Chrome through Playwright.

Agent runs were advanced by `scripts/acceptance/scripted_coordinator.py`, a
test-only stand-in for the model-driven coordinator:
- **What it uses.** It claims runs through the real D11 scheduler and acts only
  through the fenced services the coordinator uses:
  - plan publication;
  - one consolidated question;
  - `run_audit` through the E03 tool registry (executed by the real scientific
    worker);
  - effect reconciliation and finalization.

  It then releases its lease the way `Scheduler.advance` does, without a graph
  checkpoint.
- **How it decides.** Its decisions come from the objective text: always audit
  the selected dataset, and ask about units when the goal mentions units.
- **Configuration.** The API was configured with pinned-format placeholder
  model IDs and bounds so run admission is available. The placeholder
  `ANTHROPIC_API_KEY` is never sent, because no agent worker is started.

`scripts/acceptance/provision_policy.py` performs the operator's policy grant.
The product has no policy-write route, and new uploads are not authorized until
an operator grants them (see A11).

## Defects found and fixed

- **Stale result link.** A completed run's result could be missing from the
  workspace's artifact snapshot. The card then read "Trace artifact · not in
  the loaded project snapshot yet" for up to one idle poll (10 s). The card now
  requests an immediate artifact read when a published result is missing. The
  workbench also queues a forced read that arrives during a poll instead of
  dropping it.
- **Run status label.** The run's status row is now a labelled group ("Run
  status"). Tests and assistive technology can then tell the run's state apart
  from its plan steps' badges.
- **`private-access.spec.ts` was not anonymous whenever login env vars were
  set.** Under the test runner, `request.newContext()` inherits the config's
  HTTP credentials. It now passes `httpCredentials: undefined`. Before the fix,
  the gate itself was verified with curl: all five paths returned 401.
- **`workflow.spec.ts` predated A07/A08.** It now chooses the assessed
  benchmark run explicitly, and exports through **Export project** →
  **Inspect archive**.

## Reproduce

```sh
# Generate an ignored env file with independent secrets, WB_AGENTS_ENABLED=1,
# pinned-format model IDs with matching WB_AGENT_MODEL_BOUNDS, and a placeholder key.
docker compose -p a10 --env-file <env> build
NPX=npx CHROMIUM_EXECUTABLE=<chrome> sh scripts/acceptance/run_a10.sh <env>
```

The script:
1. brings up postgres, api, worker and web;
2. runs the scripted coordinator in the API container for up to 30 minutes;
3. exports the env file (so Playwright has the login credentials);
4. runs the spec.

The spec stops and restarts the `worker` and `api` services itself. Run
`private-access.spec.ts` and `workflow.spec.ts` against the same stack with
the same login env.

## Not run, and why

- **Hosted acceptance (Render).** Not performed by decision. D06's runbook
  section 7 remains the procedure, and D06 is still blocked. Hosted redeploy
  recovery and HTTPS/private-network checks remain open.
- **Live provider.** No model provider was called. The acceptance proves the
  product's run lifecycle, controls, streaming, persistence and UI against the
  real stack, not model planning quality. E15 owns live evaluation.
- **Scope of the scripted runs.** They exercise audit-only plans. Split,
  baseline, specialist and finalization-with-report paths through a real
  coordinator were not run in the browser (C10/E13 backend suites cover them).
- **SSE through the stack.** Checked with curl through the password-gated Next
  proxy on this stack:
  - `/stream` returns `text/event-stream` with `no-store`;
  - `after=2` replays events 3 onward;
  - a forwarded `Last-Event-ID: 3` starts at event 4.

  The browser reconnect case checks de-duplication after an API outage, not
  which transport was active.
- **One unexplained refusal.** In the first stack run, the scripted
  coordinator's first `run_audit` dispatch was refused ("Tool call was not
  admitted"; the error code was not logged then) and succeeded on the next
  tick. It did not recur in four later full runs. The driver now logs the
  status, error code and message.
- **Host sleep.** One earlier run overlapped a host sleep. Its audit job ended
  `JOB_TIMED_OUT` ("Claim expired before publication") after about an hour.
  That run is not counted.
- **Not covered.** Two operators, multiple browsers at once, and non-Chrome
  browsers.
