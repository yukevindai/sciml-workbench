# C02 — ChemData Auditor integration

Status: implemented and locally verified September 19, 2026. Prerequisites: C01 and B03. Existing uncommitted C01 changes were preserved.

## Changed behavior

- `run_audit` now returns typed `AuditOutput` / `AuditReport` / `AuditFinding` values using only the pinned public auditor. Requested configuration is detached from caller data; upstream effective configuration, findings, row references, details, checks and metadata remain intact.
- The internal result explicitly distinguishes completed execution from scientific acceptance (`not_assessed`) and identifies the SHA-256 of original uploaded bytes separately from the upstream dataframe fingerprint.
- Invalid upstream configuration/input raises a classified `AuditInputError`; the task boundary records `VALIDATION_FAILED` without publishing an audit artifact. Completed audits with error-severity findings remain successful executions rather than failed jobs or falsely accepted science.
- The shared scientific service consumes the typed output for manual and scoped action callers. Report replay writes the same upstream JSON shape as before. Persisted Audit 1.0 records, HTTP/schema contracts, dependency pins and database migrations are unchanged.

The [integration guide](../audit-integration.md) describes the Python boundary and downstream responsibilities. New fixtures contain clean data and deliberate duplicates, out-of-bounds values, missing numeric values and missing provenance. No scientific algorithm or repair logic was copied into workbench.
